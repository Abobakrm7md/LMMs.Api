# Agent.Domain — entities and core model

The domain layer holds every concept the rest of the system talks about. It is completely framework-free: **no package references, no project references** — nothing here knows about ASP.NET Core, EF Core, Ollama, or JSON.

- **Project:** `Agent.Domain/Agent.Domain.csproj` (`net9.0`)

The project contains three distinct models, each in its own namespace.

## `Agent.Domain.Conversations` — ephemeral agent transcript

In-memory message log the agent uses while planning and answering (distinct from the persisted entities below).

| Type | Notes |
| --- | --- |
| `MessageRole` | `System`, `User`, `Assistant`, `Tool` |
| `Message` | Immutable record: role + content |
| `Conversation` | Append-only list with `Add(Message)` and `TrimToLast(count)`; throws `ArgumentOutOfRangeException` for negative counts |

## `Agent.Domain.Planning` — plans and directives

| Type | Notes |
| --- | --- |
| `PlanKind` | `DirectAnswer`, `SingleTool`, `MultiStep` |
| `Plan` | `Goal`, `Kind`, `Steps`; factory `Plan.Direct(goal)` creates a step-less direct plan |
| `PlanStep` | `Id`, `Description`, optional `Tool` name, `Input` dictionary (arguments for the tool; may contain `{{step1}}`-style placeholders resolved by the executor) |
| `ExecutionAction` | `Continue`, `ExecuteStep`, `Complete`, `Abort` |
| `ExecutionDirective` | The planner's adaptive answer during execution; factories `Continue(reason)`, `Complete(reason)`, `Abort(reason)`, `Run(step, reason)` |

## `Agent.Domain.Tools` — execution outcomes

| Type | Notes |
| --- | --- |
| `ToolResult` | `StepId`, `Description`, `ToolName`, `Arguments`, `Output`, `Succeeded`, `IsEmpty`, `Error`. Factories `Success(...)` / `Failure(...)`. **Invariant:** a successful call with an empty/whitespace output is downgraded to a failure (`"Empty tool result"`) so the agent never treats silence as data. |
| `ExecutionResult` | The plan, all step results, plus `Completed` / `Aborted` / `StatusDetail` summarizing the run |

## `Agent.Domain.Persistence` — SQL-backed entities

Plain POCOs mapped by EF Core in the infrastructure layer. All carry a `RowVersion` concurrency token (except `ToolExecution`) and `datetimeoffset` audit stamps.

### `ApplicationUser`

| Member | Notes |
| --- | --- |
| `Id` | `Guid` primary key, generated by the app (`Guid.NewGuid()`) |
| `Email` / `NormalizedEmail` | Unique login identifier; normalized form used for case-insensitive matching |
| `UserName` / `NormalizedUserName` | Second unique identifier; login accepts either |
| `DisplayName` | Shown in the UI |
| `PasswordHash` | ASP.NET Core Identity hash format |
| `CreatedAt` / `UpdatedAt` / `LastLoginAt` | Audit timestamps (login stamps `LastLoginAt`) |
| `Conversations` | Navigation collection; cascade-deleted with the user |

### `Conversation` (persisted)

| Member | Notes |
| --- | --- |
| `Id` / `UserId` | PK + owner FK to `ApplicationUser` |
| `Title` | `"New chat"` by default; auto-renamed from the first prompt |
| `NextMessageSequence` | Monotonic counter; source of each message's `SequenceNumber` (DB check constraint `>= 0`) |
| `CreatedAt` / `UpdatedAt` / `LastMessageAt` | Audit + list ordering (`UpdatedAt` desc) |
| `Messages` | Navigation collection; cascade-deleted |

### `ConversationMessage`

| Member | Notes |
| --- | --- |
| `Id` / `ConversationId` | PK + FK; unique index on `(ConversationId, SequenceNumber)` |
| `SequenceNumber` | 1-based ordering within the conversation; used as the paging cursor (`beforeSequence`) |
| `Role` | `ConversationMessageRole`: `User = 1`, `Assistant = 2` (stored as `byte`) |
| `Status` | `ConversationMessageStatus`: `Streaming = 1`, `Completed = 2`, `Cancelled = 3`, `Failed = 4` (stored as `byte`). Assistant messages start as `Streaming` placeholders and are finalized by the turn service. |
| `Content` | `nvarchar(max)`; user messages include a `📎 <filename>` marker when an attachment was sent |
| `ModelName` | Optional model identifier for the answer (≤ 128 chars) |
| `ToolExecutions` | Navigation collection of tool calls made for this answer; cascade-deleted |

### `ToolExecution`

Audit record of one tool call: `AssistantMessageId` FK, `StepNumber`, `ToolName` (≤ 128), `Description`, `ArgumentsJson`, `Output`, `Error`, `Succeeded`, `StartedAt` / `CompletedAt`. Persisted as each tool completes so audits survive a failed or cancelled turn.
